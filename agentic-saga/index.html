Agentic Saga

Let an AI agent run multi-step jobs it cannot leave half-done: it proposes the next step, and fixed rules undo finished work newest-first if the job fails.

0.1.0 · Python 3.12/3.13 · Linux/macOS · Not on PyPI

Try the demo View on GitHub

The problem

A checkout touches services that cannot share one database transaction: reserve stock, charge the card, book delivery. If delivery is refused after the charge, the card must be refunded and the stock released, in that order, without doing either twice.

Letting a model decide is worse: it should not choose when to refund or read a lost reply as “paid” or “not paid”. Agentic Saga splits the job. The agent proposes one step from a short list allowed right now; ordinary Python rules in a Temporal Workflow check that choice, run it, and record it. If the job cannot be proven done, the workflow undoes confirmed steps newest-first.

What it does

  • Keeps the model bounded. Each turn it sees the goal, current facts, and only currently allowed steps, then proposes one; the Workflow rejects anything else. Turn, tool-call, time, and token budgets cap it.
  • Pairs every effect with its undo. Each changing step names its reversing step, and confirmed effects are compensated in reverse order. The agent never chooses an undo or its timing.
  • Records the run in Temporal. Confirmed work survives a crash, Activities retry, and histories replay deterministically.
  • Asks before repeating. A lost provider reply is reconciled by the operation’s stable ID before any retry or compensation.
  • Requires proof. A read marked proof_for_success must return verified: true before the job can finish; otherwise the job compensates. A person is asked only when the undo cannot be proven.

Quickstart

You need uv, Git, and a connection. uv fetches a matching Python, the dependencies, and Temporal; no account or API key is needed.

git clone https://github.com/gainratio/agentic-saga.git
cd agentic-saga
uv run poe demo

That starts a throwaway Temporal server, runs a simulated checkout, and opens the Flight Recorder. The agent is scripted, the shop simulated; no model is called.

To use it in an application, install from Git; there is no PyPI package yet:

uv add "agentic-saga @ git+https://github.com/gainratio/agentic-saga"

The smallest complete program, examples/quickstart/trip.py, books a flight and a hotel, fails the final check on purpose, and cancels both bookings. From the clone:

uv run python -m examples.quickstart.trip
Forward steps: book_flight -> book_hotel -> confirm_trip
Undo steps:    cancel_hotel -> cancel_flight
Outcome:       compensated_verified

A real example

The trip program pairs each change with its undo, then names the allowed order and proof read. Abridged from trip.py:

def build_registry(forward: list[str], undo: list[str]) -> ToolRegistry:
    return ToolRegistry(
        (
            booking("book_flight", "cancel_flight", forward),
            booking("book_hotel", "cancel_hotel", forward),
            booking("cancel_flight", None, undo),
            booking("cancel_hotel", None, undo),
            ReadToolDefinition("confirm_trip", Trip, TripCheck, FakeTripCheck(forward)),
        )
    )

WORKFLOW_TOOLS = (
    WorkflowTool(name="book_flight", kind="effect", compensation_tool="cancel_flight"),
    WorkflowTool(name="book_hotel", kind="effect", compensation_tool="cancel_hotel",
                 prerequisites=("book_flight",)),
    WorkflowTool(name="confirm_trip", kind="read", proof_for_success=True,
                 prerequisites=("book_hotel",)),
)

booking(...) wraps a provider call; confirm_trip is a read-only check. The undo name appears as compensate_with on the registry entry and compensation_tool on the workflow tool; if they differ, the step fails with tool_contract_mismatch.

Variants:

uv run poe demo happy-path
uv run poe demo lost-response
uv run poe demo compensation-failure
  • happy-path: every step works.
  • lost-response: the card company’s reply is lost; the saga reconciles instead of charging again.
  • compensation-failure: the refund cannot be confirmed, so a person must sign off; the demo plays that person.

Limits

  • Unreleased. 0.1.0 has no PyPI package or tagged release; install from Git. Python 3.12 or 3.13 on Linux or macOS only.
  • Your providers must cooperate. Every side-effecting call needs a stable request ID and a lost-reply lookup. Agentic Saga cannot make a non-idempotent API safe, and the example services are simulations.
  • You need Temporal. The demo starts a throwaway server; real use needs a local server or Temporal Cloud.
  • It does not judge the model. Tests never call a paid model, so live step choice is not evaluated.
  • Traces are not signed. They are checked for internal consistency and content hashes; anyone who can edit a trace file can rewrite it.

Use a database transaction when every change is in one database. For a fixed sequence, Temporal alone is simpler. If the agent only reads or drafts, call tools directly; if you can write the routes by hand, plain if/else is enough.

Security and data handling

Temporal keeps Workflow and Activity payloads: inputs, results, failure details, and Update arguments. The built-in converter is for public-safe data. Use opaque business identifiers, keep secrets and documents by reference, resolve credentials inside Activities, and trim provider receipts to reconciliation fields. Redaction does not erase values already in Temporal history.

Private payloads require client-side encryption with a shared Payload Codec backed by a KMS, a dedicated Namespace with least-privilege access, and application authentication for every human decision. The opt-in OpenRouter path authenticates with your OPENROUTER_API_KEY and sends the goal, current facts, and allowed steps; the library does not enforce provider spend. The Flight Recorder binds to 127.0.0.1, is read-only, and is not an authenticated multi-user service. See SECURITY.md.

FAQ

Do I need an API key or a Temporal account to try it?

No. The demo starts a throwaway Temporal server with a scripted agent and simulated shop; no key or account.

Can the agent decide when to refund or undo?

No. Undo tools are registered but never offered to the agent. The Workflow derives the order from confirmed effects and compensation pairs, newest-first.

What happens when a provider’s reply is lost?

The Workflow reconciles by the operation’s stable ID and asks the provider what happened before retrying or compensating. If the outcome cannot be proven, it stops for an authenticated person.

Is it on PyPI?

No. 0.1.0 has no package or tagged release; install from GitHub. It supports Python 3.12 and 3.13 on Linux and macOS.

Can I use a different model?

Yes. The default is Jev through OpenRouter; Jev direct through TypeSafe, any tool-calling model through Pydantic AI and OpenRouter, and a scripted driver also work. Tests never call a paid model.
