Agentic Saga

Resolve free-form customer order concerns safely: an LLM triages the message, a constrained decision engine picks one allowed step at a time, and Temporal undoes finished steps newest-first if a downstream check fails.

Why four layers

Imagine a customer writes in: “I paid $79 four days ago for order_8841 and still haven’t received it — please rush a replacement or refund me.” Resolving that touches inventory, billing credits, and an express courier before the depot confirms whether the original parcel was stopped. If the depot reports that the original parcel was just scanned onto a delivery truck, every new action has to be undone in strict reverse order so you do not ship twice or give away free credit.

Pure fixed workflows cannot read messy human complaints or decline off-topic chat, while unconstrained tool-calling agents should never improvise refund order or guess whether a timed-out request succeeded. Agentic Saga gives each layer the one job it is actually good at.

The 4-layer compensating architecture

  1. Agent / LLM Concern Intake (start_concern_saga). Reads a free-form user prompt via a structured Pydantic AI classifier or local triage driver. If the message is not an order processing issue (for example, “What is the weather in Seattle this weekend?”), it politely replies that it is not an order processing issue and stops immediately with 0 workflows started and 0 tool calls.
  2. Constrained Step Decision Engine (Jev / PydanticAI). Inside the agentic_saga.decide Activity, sees only the steps whose prerequisites are satisfied right now and proposes one forward step at a time. Undo tools are never offered to the model.
  3. Durable Workflow State (Temporal). Enforces turn, tool, time, and token budgets, reconciles lost provider replies by stable operation ID before retrying, verifies proof_for_success reads, runs newest-first compensation automatically when a check fails, and pauses in HUMAN_REQUIRED when an undo reply itself is uncertain.
  4. Deterministic Paired Tools (ToolRegistry). Every side-effecting tool has frozen Pydantic input/output schemas, a deterministic idempotency key, a reconcile() lookup, and an explicit compensate_with reverse tool checked against the workflow definition before execution.

Quickstart

You need uv and Git. uv fetches a matching Python, dependencies, and a local Temporal test server; no account or API key is required.

git clone https://github.com/gainratio/agentic-saga.git
cd agentic-saga
uv run poe demo

That runs the customer concern for order_8841 on a throwaway local Temporal server and opens the live Flight Recorder: replacement held, $15 courtesy credit added, express courier booked, depot check discovers the original parcel on the truck, and all three steps are reversed newest-first (compensated_verified).

Try an unrelated prompt to see Layer 1 politely decline before starting Temporal:

uv run poe demo not-an-order
uv run poe demo --prompt "Can you write me a haiku about rain?"

Other order-concern and classic checkout scenarios:

uv run poe demo happy-path
uv run poe demo lost-response
uv run poe demo compensation-failure
uv run poe demo-checkout

To depend on the library in Python (install from Git; there is no PyPI package yet):

uv add "agentic-saga @ git+https://github.com/gainratio/agentic-saga"

A minimal paired-tool contract

The smallest self-contained program, examples/quickstart/trip.py, pairs each forward action with its undo and requires a final proof read:

def build_registry(forward: list[str], undo: list[str]) -> ToolRegistry:
    return ToolRegistry(
        (
            booking("book_flight", "cancel_flight", forward),
            booking("book_hotel", "cancel_hotel", forward),
            booking("cancel_flight", None, undo),
            booking("cancel_hotel", None, undo),
            ReadToolDefinition("confirm_trip", Trip, TripCheck, FakeTripCheck(forward)),
        )
    )

WORKFLOW_TOOLS = (
    WorkflowTool(name="book_flight", kind="effect", compensation_tool="cancel_flight"),
    WorkflowTool(name="book_hotel", kind="effect", compensation_tool="cancel_hotel",
                 prerequisites=("book_flight",)),
    WorkflowTool(name="confirm_trip", kind="read", proof_for_success=True,
                 prerequisites=("book_hotel",)),
)

The undo name appears on both the registry entry (compensate_with) and the workflow tool (compensation_tool); if they disagree, execution fails closed with tool_contract_mismatch before calling the provider.

Limits

  • Install from Git. 0.1.0 is tagged on GitHub without a PyPI package yet; supports Python 3.12 and 3.13 on Linux and macOS.
  • Your providers must cooperate. Every side-effecting call needs a stable request ID and a lost-reply lookup. Agentic Saga cannot make a non-idempotent API safe, and the bundled order-concern and checkout services are simulations.
  • You need Temporal. The demo starts a throwaway local server; production deployments run against a Temporal cluster or Temporal Cloud.
  • Offline tests do not score live model quality. CI verifies deterministic safety invariants without calling paid endpoints; optional live OpenRouter evaluation suites run separately.
  • Traces are integrity-checked, not cryptographically signed. Content hashes catch accidental drift, not deliberate edits by someone with write access to trace files.

Use a single database transaction when every write lives in one database. Use plain Temporal when both intake and step order are completely fixed. Use Agentic Saga when free-form user concerns and flexible step choice must coexist with strict compensating transactions.

Security and data handling

Temporal records Workflow and Activity inputs, results, failure details, and Update arguments. Keep payloads to opaque business identifiers (such as order_8841), resolve credentials inside Activities, and trim provider receipts to reconciliation fields. Redaction helpers scrub common secret keys before persistence, while private customer payloads in production should use a KMS-backed Temporal Payload Codec, a dedicated Namespace, and authenticated operator sign-off for HUMAN_REQUIRED updates. See SECURITY.md.

FAQ

What happens if a user sends a prompt unrelated to orders?

start_concern_saga returns a polite DeclinedConcern reply explaining that the message is not an order processing issue. Zero Temporal workflows are started and zero tools are invoked.

Do I need an API key or a Temporal account to try it?

No. uv run poe demo starts a throwaway local Temporal server with local triage and simulated order tools; you can plug in Pydantic AI or Jev via OpenRouter when ready.

Can the agent decide when or how to undo?

No. Compensation tools are never exposed as candidate choices to the step chooser. Temporal derives the exact newest-first undo sequence from confirmed forward effects.

What happens when a provider’s reply is lost?

The Workflow calls reconcile() with the operation’s stable ID before retrying or compensating. If a compensation reply itself remains unknown, the Workflow pauses in HUMAN_REQUIRED for an authenticated support lead.
