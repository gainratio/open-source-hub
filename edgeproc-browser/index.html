@gainratio/browser

Have the browser check that downloaded data was signed by you and never changed, then keep it for offline use.

v0.4.4 · MIT · npm · GitHub

Quickstart

The problem

Many web apps download data files and use them inside the page: a product catalog, search index, price list or model. The page trusts whatever the server or CDN sends back.

If a mirror serves an old copy, or a file is changed or cut short on the way, the app uses it anyway. This package lets the page check it itself: you sign the data once at publish time, and the browser refuses anything that does not match.

What it does

The page gives a bundle URL and a public-key URL to a Web Worker, which checks the publisher's signature and downloads only the pieces it is missing.

  • Verifies the signed pointer against the Ed25519 public key or keyring you configure, refusing older sequences and, with a keyring, revoked keys.
  • Checks every chunk against its SHA-256 address. A new version replaces the old one only after every check passes; on failure, the last good version stays.
  • Keeps the checked copy in one SQLite database on OPFS, the browser's origin-private file system, so later visits fetch only changes and the page works offline after the first sync.
  • Opens a verified .sqlite file in OPFS with FTS5 full-text search, JSON1 and vector search; SQLite bundle updates fetch only the changed 64 KB pieces.
  • Reports every network request the Worker made and returns typed errors with codes: integrity, rollback, network, lock, storage, internal.

Quickstart

Install the package and Vite; the example uses Vite's ?worker import.

npm install @gainratio/browser
npm install --save-dev vite

Keep the Worker entry in your source so the bundler owns its URL:

// src/edgeproc.worker.js
import "@gainratio/browser/worker";

Then create a client, sync a signed bundle and read a checked file:

// src/main.js
import { EngineClient } from "@gainratio/browser";
import EdgeProcWorker from "./edgeproc.worker.js?worker";

const client = new EngineClient(new EdgeProcWorker());
try {
  const result = await client.sync("/bundle", "/public.key");
  const bytes = await client.readFile("prices.json");
  console.log(`verified ${result.version}`);
  console.log(new TextDecoder().decode(bytes));
} catch (error) {
  console.error(`refused (${error.code}): ${error.message}`);
}

Load it from your page with <script type="module" src="/main.js"></script>.

The publisher commands below create the bundle and public.key. The README's Try it walkthrough starts from an empty folder.

A real example

This signs a one-file catalog and writes the bundle the client loads. It needs Node 22.13+ and uv:

mkdir data
echo '{"sku": "A-100", "name": "Blue mug", "price": 12.5}' > data/prices.json
uvx --from 'edge-proc[bundles]' edgeproc keygen --out keys
uvx --from 'edge-proc[bundles]' edgeproc publish --src data --origin-dir public/bundle \
  --key keys/private.key --bundle-id prices --version v1 --sequence 1
cp keys/public.key public/public.key

It writes latest, a manifest and content-addressed chunks under public/bundle/. Keep --sequence 1 and raise it on every publish: the browser refuses a pointer without a sequence and uses it to reject rollbacks. Run npx vite in the project root and open the page.

To see a refusal, flip one byte in the first chunk and open the page in a private window, which does not reuse the checked copy:

node -e "const fs=require('fs'),d='public/bundle/chunk/',p=d+fs.readdirSync(d)[0],b=fs.readFileSync(p);b[9]^=1;fs.writeFileSync(p,b)"

Sync then fails with refused (integrity) and a message that the chunk failed its content-address check; run the command again to restore the byte.

Limits

  • You need a publisher. The package checks bundles; it does not sign or publish them. Today that is the Python edgeproc publish command.
  • Data flows one way. It does not sync user edits back to a server.
  • It does not know what your data means. It hands your app checked bytes; the schema and interpretation are yours.
  • It cannot protect a compromised page. A malicious extension, or an attacker who controls the public-key URL, is out of reach. Serve the key over HTTPS from your own site, apart from the data mirror, and keep the private key off the web server.
  • Browser coverage is uneven. Chromium gets the full browser suite; Firefox and WebKit get one cross-browser test that, for Playwright's WebKit, covers the OPFS fallback. Real Safari is not tested.
  • It is pre-1.0; only the latest published version gets fixes.

If you fully trust your server and CDNs, plain fetch is simpler. Use Subresource Integrity for a few build-time-known files, a service worker such as Workbox for an offline app shell, and a hosted database when edits must sync back.

Security and data handling

  • The key URL is the trust root. The public key or edgeproc.keyring/v1 file is fetched with no-store. Whoever controls it controls trust, so host it over HTTPS and separately from mutable bundle content.
  • Nothing is promoted until every check passes. The Worker verifies the signature, bounds compressed and expanded bytes, checks the manifest hash, every chunk hash and the reassembled file. Invalid bytes never become a degraded result.
  • The OPFS chunk store is untrusted at rest. Every chunk is re-hashed on read, a bad row is deleted, equal-sequence disagreement fails closed, and a trigger prevents lowering the rollback floor.
  • An OPFS fallback is reported. The default keeps an in-memory SQLite cache for the Worker's life, reports cacheBackend: "sqlite-memory", and re-downloads it next session. Pass cacheFallback: "none" to refuse that and fail with EngineStorageUnavailableError without downloading.
  • Pinned local WASM. The chunk store and optional SQLite subpaths use local WASM assets and do not load code from a CDN.

Read the threat model and vulnerability policy.

FAQ

Is @edgeproc/browser the same package?

It is the old, deprecated name. Install @gainratio/browser; the README documents 0.4.4.

Do I need Vite?

The examples use Vite's ?worker import. Without a bundler, use spawnEngineClient() from @gainratio/browser/spawn.

Do I need COOP/COEP headers?

Only the optional SQLite app-state store needs a cross-origin-isolated page. The rest of the package does not.

What happens when the origin is unreachable?

If a verified copy is already cached, sync serves it offline. When its signed expires_at has passed, the result is marked expired: true; treat that as a failure if the app must never show stale data.

Can I use it commercially?

Yes. The package is MIT-licensed; the LICENSE is in the repository.
