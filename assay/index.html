Assay

Turn measurements on different scales into one score that shows exactly how it got there.

Prerelease 0.5.0.dev6 on PyPI and 0.5.0-dev.6 on npm · Python 3.13+ · Node 22.13+

View on GitHub Quickstart

The problem

Apps rank laptops, vendors, applicants, and software releases. The score usually comes from arithmetic that mixes hours, dollars, and kilograms, where lower is sometimes better. When someone asks why an item got 0.66, the explanation is buried in code, and a second implementation in another language slowly drifts from the first.

Assay moves that arithmetic into a declared request: a method, a version label for the formula, and each measurement's scale or coefficient. It validates the request, combines the measurements in declared order, and returns the score with every intermediate number. The Python and TypeScript packages follow the same contract and are checked against shared test cases.

What it does

  • Normalizes each measurement to 0–1 for weighted_mean and minimum, using its declared minimum, maximum, and higher_is_better/lower_is_better direction; additive keeps raw values.
  • Combines them with exactly three methods: weighted_mean (weights become shares of the total), additive (raw values times nonnegative coefficients, with explicit add/subtract operations and an optional intercept), or minimum (the first weakest normalized row decides).
  • Checks the full request before arithmetic. Unknown fields, duplicate IDs, non-finite numbers, invalid scales or intervals, and method-shape errors are refused with stable assay.* codes; no partial score is returned.
  • Returns every row's raw and normalized values, declared weight, coefficient, and contribution, plus the score, optional propagated interval, method version, and order-preserving inputs_hash.
  • Ships as assay-engine on PyPI (base dependency: Pydantic) and @gainratio/assay on npm (no runtime dependencies), with shared vectors checking that all three methods agree. Optional Python extras: cli adds assay compose/measure/explain; metrics adds scientific calculators.

Quickstart

Python 3.13 or newer. This is the exact prerelease; no stable release exists yet.

pip install assay-engine==0.5.0.dev6

Score a laptop on battery life (higher is better), price, and weight (lower is better). Battery and price count twice as much as weight.

from assay import compose, parse_request

def measure(name, value, worst, best, importance):
    direction = "higher_is_better" if best > worst else "lower_is_better"
    scale = {"minimum": min(worst, best), "maximum": max(worst, best),
             "direction": direction}
    return {"id": name, "label": name, "value": value, "scale": scale,
            "interval": None, "weight": importance}

laptop = [measure("battery_hours", 10, worst=0, best=20, importance=2),
          measure("price_usd", 900, worst=2400, best=400, importance=2),
          measure("weight_kg", 1.4, worst=3.0, best=1.0, importance=1)]
request = parse_request({"method": "weighted_mean",
                         "method_version": "laptop.v1",
                         "clamp": "reject", "components": laptop})
result = compose(request)
print(f"score: {result.score:.2f} out of 1")
print(result.inputs_hash)

Real output from that script:

A real example

The same laptop score in TypeScript returns the same number and fingerprint. Node 22.13 or newer:

npm install @gainratio/assay@0.5.0-dev.6
import { compose, parseRequest } from "@gainratio/assay";

const measure = (name, value, worst, best, importance) => ({
  id: name, label: name, value, interval: null, weight: importance,
  scale: {
    minimum: Math.min(worst, best), maximum: Math.max(worst, best),
    direction: best > worst ? "higher_is_better" : "lower_is_better",
  },
});
const result = compose(parseRequest({
  method: "weighted_mean", method_version: "laptop.v1", clamp: "reject",
  components: [
    measure("battery_hours", 10, 0, 20, 2),
    measure("price_usd", 900, 2400, 400, 2),
    measure("weight_kg", 1.4, 3.0, 1.0, 1),
  ],
}));
console.log(`score: ${result.score.toFixed(2)} out of 1`);
console.log(result.inputs_hash);

That prints score: 0.66 out of 1 and the same inputs_hash as the Python run.

For a larger committed example, build both packages and replay the seven-component Northstar score in a checkout:

Limits

  • It does not decide policy. Your app chooses measurements, weights, thresholds, bands, hard gates, abstention, and pass or fail; Assay performs only the arithmetic you declared.
  • It checks form, not truth. It checks that an input is well formed, not that it is true, complete, fresh, or fair.
  • It does not learn. There is no machine learning; the weights are the ones you wrote.
  • The fingerprint is not evidence. inputs_hash is a deterministic replay fingerprint, not authentication or tamper evidence, and anyone can compute it. Sealing evidence is the separate Avow project.
  • It is a prerelease. The API may change before 0.5.0. Python's optional metric calculators are broader than TypeScript's, and complete optional-metric parity is not claimed.

For a tiny formula nobody will ever question, a few lines of your own code is simpler; if people are doing the scoring, use a spreadsheet.

Security and data handling

Both packages compute locally. Python's base package has no network, telemetry, subprocess, worker, cache, or file I/O; TypeScript's has no runtime dependencies, network, telemetry, storage, DOM, or worker access. Neither keeps a hidden copy.

The CLI is the only core file surface: one caller JSON file up to 1 MiB, one explicit output path, atomic replacement, and no input/output aliasing.

Results retain raw values, so saved results need the same care as their source data; you own retention, access, deletion, backup, and logging. inputs_hash is not tamper evidence. Report vulnerabilities through GitHub's private advisory flow.

FAQ

Is there a stable release?

No. The authorized prerelease pair is assay-engine 0.5.0.dev6 on PyPI and @gainratio/assay 0.5.0-dev.6 on npm. The API may change before 0.5.0; check both registries.

Do Python and TypeScript return the same result?

For the three composition methods, shared vectors check field and component order, JSON scalar kinds, binary64 values, and the exact inputs_hash. That is semantic parity, not byte-identical JSON output from each language's serializer. Complete parity for the optional calculators is not claimed.

What does inputs_hash prove?

It fingerprints the complete validated request, including method, version, order, labels, scales, values, intervals, weights, operations, intercept, and boundary policy. Use it to compare a replay with the original request. It does not authenticate the request or show that nobody changed it.

What happens when a request is invalid?

Assay returns no score. It refuses the request with a stable, value-free assay.* code such as assay.out_of_range; the rejected value is not echoed.
