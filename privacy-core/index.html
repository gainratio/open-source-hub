TypeScript library · on-device

privacy-core

Hide card numbers, emails and ID numbers from AI models, then restore them in the reply — on the device.

Node 22.13+ and browsers (tested in Chromium) · MIT · v0.3.2

The problem

A banking or support app's “ask the AI about this” button starts with whatever the user pastes in. That text often holds card numbers, account numbers and email addresses, and sending it as-is puts every value in front of the AI provider. Most teams drop the feature or hope nobody pastes anything sensitive.

privacy-core moves the boundary into the client: detection runs on the device, and the user approves the exact text that leaves.

What it does

  • Finds structured identifiers locally with a fixed ruleset and validators: Luhn for cards, mod-97 for IBANs, SSA rules for unseparated SSNs. No AI model is used.
  • Replaces each value with a stable typed label such as [CARD_1]; the real value stays in an in-memory Vault.
  • Makes approval a type: redactForEgress() returns a proposal, approve() turns it into the sendable payload, and a raw string is a compile error.
  • Restores the reply locally with rehydrate() using the same vault; a mismatched or unresolvable placeholder fails closed.
  • Signs opt-in allow/deny receipts through @gainratio/avow; a receipt carries a SHA-256 hash of the redacted text, not the text.
  • Runs offline with NoLLMProvider, or calls any OpenAI-compatible endpoint with OpenRouterProvider.

Quickstart

You need Node 22.13 or newer; the package is ESM-only. After install, the offline example needs no account, API key or network call.

mkdir try-privacy-core && cd try-privacy-core && npm init -y && npm install @gainratio/privacy-core

Save this as example.mjs, then run node example.mjs:

import { approve, guardedProvider, NoLLMProvider, redactForEgress, rehydrate, Vault } from "@gainratio/privacy-core";

const text = "Maria Lopez asked: refund $482.10 to card 4242 4242 4242 4242 and email maria@example.com.";
const vault = new Vault();
const log = (entry) => console.log("[log]", entry.kind, entry.placeholders.join(" "));

const pending = await redactForEgress(text, vault, log);
console.log("will send:", pending.redactedText);

const payload = approve(pending, log);
const reply = await guardedProvider(new NoLLMProvider()).complete(payload);
const answer = reply.redactedText.split("\n")[1];

console.log("AI saw:", answer);
console.log("you see:", rehydrate(answer, vault, payload.vaultRef));

NoLLMProvider echoes the labels back, so the loop runs offline and prints the outgoing text, the reply, and the restored answer.

A real example

Two cases beyond the minimal loop: a raw send the compiler refuses, and a reviewed call to a real model.

1. The send that will not compile

import { NoLLMProvider } from "@gainratio/privacy-core";

await new NoLLMProvider().complete("my card is 4242 4242 4242 4242");

tsc stops with:

error TS2345: Argument of type 'string' is not assignable to parameter of type 'RedactedPayload'.

2. A reviewed send to a real model

import {
  approve, guardedProvider, makeProvider, redactForEgress, rehydrate, Vault,
} from "@gainratio/privacy-core";

// Host-supplied: makeProvider throws MissingApiKeyError if this is unset.
const { provider } = makeProvider({ apiKey: process.env.OPENROUTER_API_KEY });
const guarded = guardedProvider(provider);

const vault = new Vault();
const pending = await redactForEgress(
  "Grace Hopper, card 4242 4242 4242 4242, was charged $482.10 at Whole Foods on 01/14/2026.",
  vault,
);
const payload = approve(pending, (entry) => console.log("[audit]", entry.kind));
const reply = await guarded.complete(payload);
console.log(rehydrate(reply.redactedText, vault, payload.vaultRef));

The library reads no environment variables; the host passes the key in server-side.

Limits and when not to use it

  • Only the recognized formats are found. Cards, emails, US/NANP phones, SSNs, IBANs, labeled account and routing numbers, dollar amounts, US dates, three demo names and five demo merchants. General names, addresses and free text are not detected; the review step is the backstop.
  • Redaction is not anonymization. Surrounding words can still identify someone: “$482.10, insurance, early January”.
  • The vault does not persist. It lives in process or tab memory and clears on reload; an encrypted IndexedDB vault is planned, not shipped.
  • A compromised device is out of scope. A malicious extension, XSS bug or bad dependency can read the vault and a browser-held signing key. Browser key custody is same-origin, not hardware-backed.
  • The provider's handling is out of scope. The library controls what leaves, not what the AI company does with the labeled text.
  • Budgets are bounded. Redaction accepts at most 512 KiB per call; the OpenRouter adapter defaults to a 30-second deadline and a 1 MiB response cap.

Need wider coverage? Microsoft Presidio fits a Python service that needs names and places; LLM Guard's Anonymize fits a Python gateway; a hosted DLP API fits when broad detection matters more than keeping raw text local.

Security and data handling

Redaction, the vault and rehydration run on the device with no network call. Only the provider adapter sends; on the normal path it sends approved placeholder text.

Real values sit in process or tab memory and are gone on reload. Providers accept only an approved payload: assertApproved() rejects a hand-built copy by object identity with UnapprovedPayloadError, and the only raw-text escape hatch, unsafeBypass, always emits an AuditEntry.

Receipts are opt-in: guardedProvider signs each allow and deny with Ed25519 through @gainratio/avow, carrying a SHA-256 digest of the redacted text, never the text. They are tamper-evident after signing, not proof that a compromised host is trustworthy.

The demo keeps OPENROUTER_API_KEY server-side in a same-origin proxy; it never reaches the browser bundle.

FAQ

Does it run in Node and the browser?

Yes. It runs on Node 22.13+ or in a modern browser bundler; the browser path is tested in Chromium. The package ships ES modules only.

Can I use my own model or endpoint?

Yes. OpenRouterProvider takes any OpenAI-compatible chat/completions URL, and makeProvider() selects it when a non-empty API key is configured. Without a key, it throws MissingApiKeyError unless you opt into allowOffline.

Does it catch names and addresses?

No, not in general. The list has three demo names (Ada Lovelace, Grace Hopper, Alan Turing) and five demo merchants; general name and address detection is not shipped. That is why the approval screen shows the complete outgoing text.

Do I still need approve() when nothing is detected?

Yes. “Found nothing” is not “someone said yes”: the detector finding nothing still produces a proposal, and only approve() turns that proposal into a sendable payload.

What if I really need to send raw text?

Use unsafeBypass. It always emits an AuditEntry, so a silent bypass is treated as a security bug.
